## 导入卡组

三条通道读取同一个包、返回同一份报告，按顺手程度任选一条。

### 网页端

1. 打开你的实例的**导入**页：`<你的实例地址>/import`。
2. 来源保持**上传文件**，选中 `.edeck` 文件，**导入到**选**新卡组**，点击**导入**。
3. 想先看结果而不写库，勾选**先试导入，不写入数据**。

### 公开链接

仍在同一页面，把来源切到**公开链接**，粘贴文件的直接下载地址——即仓库里 *Raw* /
*原始文件* 按钮背后的裸文件 URL。链接必须是公开 HTTPS、且直接返回包字节：分享页、
HTML 页面、需要登录的链接都会被拒绝。中文文件名复制出来是百分号编码的路径，可直接使用。

### CLI

CLI 直接连数据库，`DB_DRIVER`、`DB_DSN` 按 `serve` 的同一套设置。

```bash
# 只校验，不写任何数据
engram import --package decks/百化分.edeck --user <id|用户名> --dry-run

# 导入为新卡组
engram import --package decks/百化分.edeck --user <id|用户名>
```

`--user` 是必填项：包会归到某一个账号名下，CLI 从不替你猜是哪一个。`--target` 可选
`new_deck`（默认）、`into_deck:<id>`、`replace_deck:<id>`；`--on-conflict` 可选
`update`（默认）、`skip`、`fail`。

### MCP

`import_deck` 工具接受 `url`（同上公开直链）或 `package`（base64 编码的归档），返回同一份
导入报告。

## 包内结构

`.edeck` 是一个 zip 归档，四个条目为必填：

| 条目 | 内容 |
| :--- | :--- |
| `manifest.json` | 格式版本、导出时间、卡组名与描述、`include_*` 开关、条目计数 |
| `notes.json` | 笔记内容，与批量导入笔记的请求同构 |
| `cards.json` | 每张卡一条：`note_index`、`template`、`ordinal` |
| `preset.json` | 调度参数；`weights: null` 表示使用 FSRS 库默认权重 |

`progress.json`（导出者本人的调度状态）与 `media.json` 加 `media/…` 二进制条目是可选
项，只有导出时包含才会出现。因此「单一题型、无图片、不带进度」的包解压出来正好是那四个
必填文件。

格式说明与校验方法见 [`schema/README.md`](../schema/README.md) 与
[`schema/deck-package.schema.json`](../schema/deck-package.schema.json)。

## 收录新卡组

1. 导出时不要包含进度（`include_progress` 关掉），除非这份进度本来就要共享。
2. 入库前先做脱敏：笔记正文里不得出现真实域名、邮箱或凭据；不得出现指向其他系统私有 id
   的 `external_ref`——形如 `affine:<文档 id>:…` 的值会暴露导出它的那个实例。删掉该字段，
   或换成中性键。
3. 校验：按上文用 `--dry-run` 导一遍，JSON 形态再用 `check-jsonschema` 校验，
   见 [`schema/README.md`](../schema/README.md)。
4. 在上面的表格里补一行。
